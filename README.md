# Vision-Language Model (VLM) Research: Flood Detection

This repository contains the data pipeline and experimental setup for evaluating how well modern Vision-Language Models (specifically **Qwen 2.5 VL 7B**) can detect and analyze surface water and flooding in satellite imagery.

We use the **Sen1Floods11** dataset, which consists of 13-band Sentinel-2 optical imagery and expert hand-labeled ground truth masks.

---

## 📂 Directory Structure & Data Flow

### 1. Raw Data (`data/raw/`)
The raw dataset is downloaded from Hugging Face (`blumenstiel/Sen1Floods11`). It is stored in `data/raw/sen1floods11_v1.1/`.
*   **S2L1CHand**: Contains the Sentinel-2 13-band `.tif` files.
*   **LabelHand**: Contains the expert-labeled masks.
    *   `-1`: No data or clouds
    *   `0`: Dry land
    *   `1`: Water / Flood

### 2. Processed Baseline Data (`data/processed/`)
Generated by running `prepare_data.py`. This folder serves as the standard input for the VLM.
*   **RGB PNGs**: All 446 images are converted from 13-band `.tif` to 8-bit true-color RGB `.png` files using a 98th-percentile contrast stretch. This ensures every model sees the exact same standard image.
*   **`metadata.json`**: The central configuration file mapping every image to its ground truth and evaluation prompts. (See *Data Structures* below).

### 3. Hallucination Test Data (`data/processed_covered/`)
Generated by running `generate_covered_images.py`. This folder contains "camouflaged" versions of the processed images to test the model for hallucination.
*   **Camouflaged PNGs**: In these images, the actual floodwater/water bodies have been artificially removed. The script randomly samples *dry land* pixels from the surrounding area and pastes them over the water. If a model looks at these images and says "Yes, there is a flood", we can definitively prove it is hallucinating.

## 📄 File Descriptions

### Data & Environment Setup
*   **`config.py`**: Central configuration file defining directory paths, Hugging Face repo IDs, reproducibility seeds, and the RGB band index order.
*   **`download_data.py`**: A helper script that uses the `huggingface_hub` to download the `sen1floods11_v1_1.tar.gz` archive.

### Data Processing Pipeline
*   **`data.py`**: Contains core utility functions to match image/mask pairs, load `.tif` files, convert them to 8-bit RGB, calculate water fractions, and plot sample grids (saved to `results/figures/phase0_pairs.png`).
*   **`prepare_data.py`**: **(Run this first)** The main preprocessing script. It iterates through all 446 chips, saves standard PNGs, calculates metrics (water fraction, cloud cover, dominant quadrant), applies a >50% cloud rule, and generates three specific text prompts for each image. Saves outputs to `data/processed/metadata.json`.
*   **`generate_covered_images.py`**: **(Run this second)** The script used for the experimental occlusion testing. It generates the camouflaged images and saves them to `data/processed_covered/`.

### Model Inference
*   **`qwen_inference.py`**: A local Python script demonstrating how to load `Qwen2.5-VL-7B-Instruct` using Hugging Face `transformers` and `qwen-vl-utils` to analyze an image.
*   **`qwen_colab.ipynb`**: A Jupyter Notebook designed specifically to be run on **Google Colab's free T4 GPU**. It includes the necessary setup to load the heavy 7B parameter model using 4-bit quantization (`bitsandbytes`) so it doesn't crash due to memory limits.

## 🧬 Data Structures (`metadata.json`)

To make model evaluation simple, `metadata.json` contains everything needed for inference and scoring. Here is an example of how the data is stored for a single chip:

```json
"Bolivia_103757": {
    "image_path": "data\\processed\\Bolivia_103757.png",
    "target_label": "surface water/inundation",
    "stats": {
        "water_fraction": 0.1254,
        "nodata_fraction": 0.0,
        "dominant_quadrant": "bottom-right",
        "is_mostly_cloud": false
    },
    "prompts": {
        "free_text": "Please provide a detailed free-text report describing the presence and extent of surface water/inundation in this satellite image.",
        "structured_json": "Analyze the image for surface water/inundation. Return your analysis as a structured JSON object with the following fields: 'flood_present' (boolean), 'water_percentage' (float, 0-100), and 'location' (string, e.g., 'top-left', 'bottom-right', 'center', or 'none').",
        "pope": "Is there surface water/inundation present in this image? Answer only Yes or No."
    }
}
```

### Prompting Strategy
We query the VLM using three distinct methods to test how output format affects reasoning:
1.  **Free Text Report**: To test open-ended scene understanding and distinguish between permanent rivers vs. active flooding.
2.  **Structured JSON**: To test if the model can be used reliably in an automated pipeline returning strict data types.
3.  **POPE (Polling-based Object Probing Evaluation)**: A strict binary "Yes/No" to calculate standard hallucination/accuracy metrics.

## 🚀 How to Replicate

1.  **Setup Virtual Environment**:
    ```powershell
    python -m venv venv
    .\venv\Scripts\Activate.ps1
    pip install -r requirements.txt # (numpy, tifffile, matplotlib, huggingface_hub, pillow)
    ```
2.  **Get Data**: Run `python download_data.py` and extract the `.tar.gz` archive inside `data/raw/`.
3.  **Process Data**: Run `python prepare_data.py`.
4.  **Generate Ablations**: Run `python generate_covered_images.py`.
5.  **Run Model**: Upload `qwen_colab.ipynb` to Google Colab, or run `qwen_inference.py` locally if you have >16GB VRAM.
